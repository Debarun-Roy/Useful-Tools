# Operator-run Python ETL

Contract 0.4.0; fixed template etl-0.4.0-b4. The destination schema in etl.spec.json must already exist. This bundle never creates tables or databases. It is local operator-run software, not a UsefulTools service. UsefulTools receives specifications only, never datasets or credentials.

Use Python 3.14.3. Create a fresh environment with `python -m venv .venv`, then run `.venv/Scripts/python -m pip install -r requirements.txt` on Windows (`.venv/bin/python` on POSIX). PostgreSQL uses pinned psycopg 3.3.6, psycopg-binary 3.3.6 and tzdata 2026.4; SQLite uses stdlib sqlite3. Run `python verify.py` before use. Integrity verification checks bytes, not destination compatibility or trust in the publisher. Do not edit bundle files; regenerate when the specification changes.

Read configuration.example.json for the four environment variable names. Set sourceEnv to the local source file path, checkpointEnv and rejectsEnv to distinct external output paths. Set connectionEnv to an existing SQLite database path, or to a JSON object containing exactly host, port (integer), dbname, user, password and sslmode for PostgreSQL. All fields must be explicit; passwords may be empty only if your independently configured authentication permits it. Supported sslmode values are disable, require, verify-ca and verify-full. Inherited PG settings are removed from this child process. Credentials never belong in the bundle or command arguments. Use only trusted local directories and database endpoints.

Run `python etl.py --dry-run --source PATH` first. This needs no destination credentials and does not connect, acquire locks, inspect/checkpoint the database, change the source, or write output unless `--reject-report PATH` is explicitly supplied. Dry run validates parsing and mappings only, not database constraints. To execute, set all four variables and run `python etl.py`. CLI source/checkpoint/reject-report paths override their environment equivalents. Example files are intentionally empty (CSV includes mapped headers); copy outside this bundle and add synthetic rows compatible with your schema and its checks. Arbitrary destination constraints prevent a universal valid populated example.

CSV accepts configured UTF-8 or UTF-8-with-BOM, comma/semicolon/tab delimiters, double quotes with doubled quote escaping, no escape character, strict decoding and newline preservation. The first record is a unique nonempty header. Blank physical records are skipped. Quoted multiline values are one logical record. Width mismatches are row rejects; malformed quoting is fatal. JSON accepts a top-level array of objects, with Decimal parsing, duplicate keys and NaN/Infinity forbidden. Nested values are accepted only for JSON destination columns. Unexpected fields follow the explicit ignore/reject policy.

Sources are bounded snapshots: CSV 16 MiB, JSON 2 MiB, 100,000 logical records, 100 fields, 4,096 characters per field, 64 KiB per record, nesting 32 and 100,000 JSON nodes. JSON is finite in-memory parsing, not streaming JSON Lines. The immutable source is SHA-256 checked again around each transaction. Do not modify it during a run or resume.

Mappings apply ordered trim/lower/upper transforms followed by an explicit type conversion. Missing, null and empty-after-transform policies are distinct. Default omits the destination column; null binds SQL NULL. Empty keep is text-only. Integers enforce 32/64-bit ranges; booleans accept actual booleans, 0/1 integers or exactly true/false/0/1 strings. Decimal conversion uses no float intermediate and rejects excess precision/scale without rounding. SQLite NUMERIC storage still uses SQLite affinity and can be approximate; use PostgreSQL NUMERIC for exact persisted decimal values. Dates use declared ISO or DD/MM/YYYY format. Timestamps accept ISO with at most six fractional digits, require an offset unless explicit naive UTC policy is selected, and normalize to UTC. Named time zones are unsupported. JSON values are bounded and serialized canonically.

Destination preflight checks exact ordered column names, types, nullability and the chosen primary/unique key. It does not certify defaults, foreign keys, checks, triggers, collation, permissions or concurrent non-ETL writers. SQLite foreign keys are enabled and confirmed. PostgreSQL tables are in public. Values are parameterized, identifiers quoted. Upsert requires explicit mapped nonnullable unique key values; it updates only specified mapped non-key columns. Default-omitted and unrelated columns survive conflicts. Repeated source keys are applied in order: last accepted value wins for updated columns. No INSERT OR REPLACE or append fallback is used.

Each batch contains 1–1,000 logical rows. Strict mode validates the whole batch before writes and rolls back the current transaction on row/constraint failure; earlier commits remain. Continue mode rejects invalid rows and uses savepoints for database integrity errors. Parser corruption, connection loss, checkpoint/reject I/O and infrastructure failures are fatal, never converted into successful row rejects. Sanitized reject JSON Lines contain only logical record, mapping index and reason code; the byte cap is enforced. Raw source fields, SQL parameters, paths and driver errors are not logged.

Summary counters: read is consumed logical records; validated is records passing mapping validation (including later database rejects); committed is confirmed successful row operations, including no-change upserts; rejected is known row failures; uncommitted is read minus committed minus rejected. No inserted/updated/distinct-row count is claimed. COMMIT_OUTCOME_UNKNOWN means uncommitted includes operations whose durability is unknown; inspect the destination before retrying. Exit 0 means clean completion, 2 completed with rejects, 3 invalid input/configuration/checkpoint, 4 strict/fatal/interrupted failure. CLI syntax errors use argparse exit 2 before execution.

Checkpoint protocol: acquire OS checkpoint and destination ETL locks; check identities; create an initial zero-record checkpoint; validate batch; begin/write/savepoint; commit; append sanitized rejects; write a same-directory temporary checkpoint, flush/fsync, atomically replace. Checkpoints identify source bytes, full specification, template and destination. Resume re-parses/skips the last durable logical record, not byte lines. Run `python etl.py --resume`; insert additionally requires `--acknowledge-insert-replay` after manual reconciliation. Malformed or mismatched checkpoints fail closed. Locks are released by process exit; lock files can remain. PostgreSQL uses table-scoped advisory locking; SQLite uses a sidecar file lock. Operators must use a consistent canonical checkpoint location and trusted directories.

A crash after commit but before checkpoint can replay a batch. Upsert replays mapped values deterministically, but triggers, sequences, audit effects and concurrent writers can repeat effects. Insert replay can duplicate data or fail constraints and always requires acknowledgement. Reject files may contain replay duplicates or a crash-truncated final line; they are diagnostics, not checkpoint authority. Initial checkpoint and same-directory replace protect process interruption, not all filesystem/power-loss failure modes. There is no exactly-once guarantee. Do not delete checkpoints to conceal a failure. After changing source/specification/target, reconcile existing writes and start a distinct job explicitly.

Artifacts are UTF-8/LF, flat fixed filenames and sorted STORED ZIP entries with fixed metadata. Manifest inventory hashes exact payload bytes; manifest.json excludes itself. Its digest hashes canonical core; specificationDigest hashes canonical full request. Arrays preserve order and object keys sort. Bounds remain 100 files/5 MiB including manifest. No Python source interpolation, eval, remote source, arbitrary transformation, database provisioning or REST service is supported.
