# Security and deployment boundary

Authentication uses Password4j Argon2id m=19456 KiB, t=2, p=1, random 16-byte salts and 32-byte hashes. Two concurrent hashes maximum, no queued work. Default passwords are 15–128 code points, at most 512 UTF-8 bytes, unchanged. Unknown accounts perform dummy verification; no constant-time end-to-end claim. A future hashing policy must add bounded accepted PHC parameters and atomically rehash after successful login; this release rejects other/malformed policies.

Core auth is always present; profile is optional. Normalized lowercase ASCII username uniqueness is DB enforced. IDs and baseline user role are server assigned. Registration never logs in. Profile identity comes only from session, and only displayName/preferences are mutable. Responses/logging never include hashes/passwords/provider secrets/session or CSRF tokens except the explicit CSRF response and session cookie. Disable request-body/header logging and redact access logs at infrastructure boundaries.

Opaque HttpSession state expires by idle and absolute clocks and is invalidated at logout. Login rotates its ID and CSRF. Cookies are HttpOnly, SameSite=Lax, production Secure, no Domain, context path scoped. Restart invalidates sessions. Single-instance sessions/throttling have no distributed revocation guarantees; scaling requires approved shared-store/stickiness and global abuse protection. Container session capacity is 4096; limiter capacity 4096 keys. Per 60 seconds: login and registration each allow 30 attempts/address and 10/account, other routes 120/address. Limits precede expensive work. Retry-After reports remaining window or 60 seconds at capacity. Direct remote address is used; forwarded headers are untrusted. Anonymous bootstrap consumes address/session capacity and never establishes identity.

Every unsafe route requires an exact trusted Origin and session-bound CSRF, with only absent/expired logout exempted from a nonexistent token. It still requires Origin. No CORS is offered; deploy the client on the same origin. Existing missing stored CSRF fails closed. Old tokens fail after login. Queries and semicolon path parameters are rejected; cookie-only tracking is required. Explicit web.xml filter order covers transport, route, limits, strict bounded JSON, session, Origin/CSRF, identity, then handler. Error responses expose constant codes and random correlation IDs only.

CAPTCHA validates reCAPTCHA v3 success/action/hostname/score/freshness and required types. Provider tokens expire after 120 seconds and are single-use at Google; errors never disable verification. HTTPS provider connect/read timeouts are 2/3 seconds and response maximum 8 KiB. External test wiring may inject transport/clock via Java constructors; there is no HTTP bypass, magic credential, token whitelist, configurable provider URL or environment test mode.

Own and isolate database files/schema, supply secrets through protected environment configuration, use verified TLS, restrict network egress, enforce connector header/request/thread/time limits, monitor sanitized error/rate counters externally, and maintain reviewed dependency upgrades/backups. SQLite is for a single service instance. PostgreSQL must use a minimally privileged account. Version 1 setup is only for empty databases. Self-review and B5 tests are not independent review or production approval. Password recovery, MFA, account lifecycle, email verification, distributed sessions and advanced roles are not included.
