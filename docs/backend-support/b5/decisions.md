# B5 design decisions

Contract 0.5.0 and template java-auth-0.5.0-b5 are independent of the frozen B0 REST draft. A required core set (registration, login, logout, session, CSRF) depends on persistence, hashing, origin policy and session authentication. Profile is the only optional endpoint module. Impossible/duplicate selections fail validation. Java release-17 compilation targets Servlet 6.1/Tomcat 11; executing Java 17 is not inferred from compilation under JDK 25.

Identity policy: ASCII usernames 3–32 characters, letters/digits/underscore, lowercase with Locale.ROOT; no whitespace trimming. Passwords 15–128 Unicode code points with a 512-byte UTF-8 cap, no trimming/normalization/composition rules. Password4j 1.8.4 Argon2id m=19456 KiB, t=2, p=1, 16-byte random salt, 32-byte output, standard PHC. Bound concurrent hashes to two and perform dummy verification for unknown accounts; no constant-time HTTP claim. Malformed or unreasonable stored PHC fails safely. Future policy changes require successful-login rehash with atomic replacement and explicit compatibility tests.

Registration returns 201 without login; DB unique normalized username is authoritative. UUID user IDs and role user are server assigned. Login rotates the session identifier and CSRF state; already authenticated login returns conflict. Profile uses session identity only, allows displayName and bounded string preferences; unknown/owner/role fields fail. PATCH merges supplied fields; preferences replaces the whole map. GET session is anonymous-safe; GET csrf-token may create anonymous security state but never identity. Logout with a present session requires valid CSRF; absent/expired logout requires a trusted Origin, clears the cookie and returns 204. Unsafe methods always require exact trusted Origin; no forwarded headers trusted. No cross-origin browser support is claimed unless explicit exact-origin CORS is implemented/tested.

Session state is opaque, server-side, cookie-only, single instance and nonpersistent across restart. Production requires HTTPS, Secure/HttpOnly/SameSite=Lax, context-path cookies, idle and absolute expiry; explicit development permits only loopback HTTP. No silent environment fallback. New database initialization is explicit and versioned; it cannot migrate arbitrary schemas or reset users. All SQL values are bound. Runtime secrets are supplied through named environment variables; generated samples contain placeholders only.

CAPTCHA is reCAPTCHA v3, directly verified for register/login, with fixed Google endpoint, bounded timeouts/body/strict JSON and success/action/hostname/score/timestamp checks. Enabled mode without a secret fails startup. Disabled mode is explicit. Test clock and connection dependencies use constructor/factory injection from external test infrastructure, never a production accept-any switch or arbitrary endpoint setting. Tests instantiate the actual generated Google transport and inject only its connection factory to a loopback provider, exercising form encoding, timeout, redirect rejection and size cap as well as semantic checks. The default production constructor always uses the fixed Google HTTPS URL.

Verification-only tooling pins openapi-spec-validator 0.9.0, openapi-schema-validator 0.9.0 and jsonschema 4.26.0 with all resolved transitive versions in scripts/b5/requirements.txt. Official package references: https://pypi.org/project/openapi-spec-validator/ and https://pypi.org/project/jsonschema/ . These are isolated verifier dependencies, not generated runtime or UsefulTools application dependencies. Response validation checks formats as well as structure. Actual generated JDBC metadata reports SQLite 3.53.4 / driver 3.53.4.0 and PostgreSQL 17.11 / driver 42.7.13; Python SQLite inspection reports 3.50.4 separately.

Archive extension is opt-in project paths; existing flat policy and default assembly remain unchanged. ASCII segments, no traversal, absolute/drive/backslash/control/dot/empty components, Windows device names, case collisions or file-directory conflicts. Entries are regular UTF-8 files, deterministically sorted/STORED with prior fixed metadata and shared 100-file/5-MiB limits including manifest. User configuration is inert JSON; only fully validated package/artifact identifiers enter fixed source/XML templates.
