# B5 focused implementation self-review

This is a self-review, not independent security review. The original independent-review requirement remains a release gate before external distribution. Final execution status is exclusively in sprint-pass.md/evidence.json; this document describes scope and findings without claiming unexecuted results.

Reviewed boundaries: new contract/template 0.5.0, Java-only core/profile dependency model, additive generation dispatch/catalog, opt-in project paths, fixed source templates with inert JSON configuration, independent in-memory editor, and external disposable verification. No earlier contract/template bytes are intentionally changed, no UsefulTools auth refactor is included, and no B6 implementation is authorized.

Corrections found during implementation: the first B5 schema lacked the existing interpreter's $defs/GenerationRequest wrapper; corrected the new schema rather than changing old validation. Runtime mode/database/CAPTCHA enums now fail closed instead of interpreting unsupported values as defaults. SQLite uniqueness handling was narrowed so unrelated integrity failures remain generic service errors. The generated strict parser rejects duplicate fields, invalid UTF-8/surrogates, nonstandard JSON, excessive nesting/strings/numbers and body sizes before expensive work. Hash verification only accepts the bounded released PHC policy and performs dummy work for absent/malformed hashes.

Final determinism review found an OpenAPI required-field array derived from Map.of iteration order, which is not stable across JVM processes. Replaced it with an explicit ordered list and added an exact ordering assertion. JSON object ordering alone cannot fix array nondeterminism. Final certification re-exports the corrected document. The full matrix also tests fresh-session address throttling, authenticated-route reset, explicit initialization disabled on an empty DB, unrelated-schema rejection and unsupported version failure without deleting existing accounts.

Session review: anonymous bootstrap grants no identity and does not repair missing stored CSRF. Unsafe routes check exact Origin and stored token; only absent/expired logout omits a nonexistent token while still requiring Origin. Login rotates both ID and token. Profile identity never comes from input. Cookie clearing matches the context path and has no Domain. Explicit web.xml registration makes method checks, bounds, Origin/CSRF and authentication ordering reviewable. Production rejects non-TLS requests and ignores forwarded headers. Volatile sessions and single-instance rate limits are documented honestly.

Test corrections: browser option disability is asserted through its native HTML disabled attribute because the Playwright convenience predicate reported an option with that attribute as enabled. A manual frontend build inherited a public CAPTCHA key; browser-test builds now explicitly use an empty key, matching previous sprint verification, with no ignored CSP errors. The test clock acknowledgement had a partial-file read race; the external harness now publishes uniquely named acknowledgements atomically. JDBC runtime versions are read through the actual WAR's JDBC connection; Python's SQLite inspection version is recorded separately. These changes preserve acceptance assertions rather than suppressing failures.

Frontend review uses the React best-practices skill: lazy independent state, primitive access dependencies, abort plus revision identity, controlled inputs, explicit apply/discard for invalid JSON, accessible field/status/findings labels, text-only previews and no draft persistence. Browser tests retain drafts, reject impossible module selections, suppress stale downloads, preserve failed-export input and cover keyboard/mobile/ten themes. Visual checks inspect generated screenshots; screenshots and browser output are evidence only for their recorded builds.

Visual inspection of diagnostic-03 Aurora mobile and Crimson Dusk desktop screenshots confirmed readable controls, stacked/mobile versus two-column desktop fields, theme styling and bounded JSON preview without horizontal overflow. The screenshot region is scrolled beneath the application's fixed header; final browser screenshots and layout checks are captured again for certification. CAPTCHA review strengthened the test boundary to exercise the actual generated HTTP transport through an injected connection factory, including form encoding, redirects, oversized response and network timeout. Only external test code selects a local provider; no operator URL option is exposed.

Verification design: actual HTTP ZIP projects are independently clean-built, their packaged WARs run under local HTTPS against owned SQLite/PostgreSQL databases, and authentication uses actual register/login routes. Constructor-injected test clock/provider transport live in the external harness; no production magic password, token, URL override or test route is emitted. CAPTCHA off must cause zero provider calls. Required on/off and optional profile combinations are explicit. Historical reports are restored in finally; earlier bundles are byte pinned. Final input fingerprint must remain unchanged during certification.

Recovery correction: first full certification .b5/20260926T202609Z passed all B5-specific gates, but the B4 regression cluster exceeded its 30-second cleanup deadline. PostgreSQL logged a 74.792-second checkpoint (67.419 seconds syncing 27,106 files), then clean shutdown, with all 180 runtime cases completed. The shared disposable-cluster helper now allows pg_ctl 180 seconds (outer subprocess 195 seconds) for clean fast shutdown. It still requires exit zero and never disables fsync or ignores cleanup failure. Full certification is repeated; historical failed evidence is retained.
