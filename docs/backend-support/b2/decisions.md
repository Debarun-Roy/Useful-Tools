# B2 decisions and contract

Frozen 0.1.0/0.1.0-b0 cannot express Unicode database names, separate index names, typed defaults, checks or FK actions. They remain unchanged. Version 0.2.0 is an explicit new consumer path, not an automatic reinterpretation of old drafts. Legacy catalog version/operations remain B1-compatible; additive `generation` advertises schema-only capabilities, schemaVersion, templateVersion and targets. Other modules are explicitly unavailable for generation.

To migrate a draft deliberately: move spec.tables to request.tables; set module=schema, schemaVersion=0.2.0, templateVersion=schema-0.2.0-b2 and target to sqlite/postgresql; remove old target/options/spec wrappers; add checks arrays, index database names and explicit FK onDelete/onUpdate; wrap defaults as `{kind:"literal",value:...}` or `{kind:"currentTimestamp"}`; add decimal precision/scale and varchar length. Internal IDs now max 32 ASCII characters, names max 63 UTF-8 bytes. Review all new semantic findings. No implicit conversion or discarded field.

| Logical type | SQLite | PostgreSQL |
|---|---|---|
| integer / bigint | INT / BIGINT affinity, no range/type enforcement; INT avoids rowid auto-numbering | INTEGER / BIGINT enforced |
| decimal(p,s) | NUMERIC affinity, approximate; no fixed-point accuracy claim | NUMERIC(p,s), insertion rounds to scale |
| text / varchar(n) | TEXT; varchar length CHECK | TEXT / VARCHAR(n) |
| boolean | INTEGER with 0/1 CHECK | BOOLEAN |
| date | TEXT ISO-date convention | DATE |
| timestamp | TEXT UTC ISO convention; strftime default | TIMESTAMPTZ; CURRENT_TIMESTAMP |
| json | TEXT with nullable-aware json_valid CHECK | JSONB |

Typed defaults are primitive literals checked against the declared type, or timestamp-only currentTimestamp. Numeric defaults must fit the declared range/precision/scale without rounding. Dates are positive four-digit ISO dates, timestamps UTC Z with at most six fractional digits. Strings reject NUL, unpaired surrogates and literal CR (LF permitted). JSON default strings are strictly decoded, reject duplicate keys, NUL/unpaired surrogates, and numbers outside absolute 1e38 / 18 fractional-digit bounds. These literal limits do not claim to restrict all runtime JSON values. Missing default differs from explicit nullable SQL NULL. No raw SQL, user functions, identity/sequence options, arbitrary expressions, collations, deferred constraints or SET DEFAULT actions.

Checks are a bounded list of `{column: stableColumnId, op: eq|ne|lt|le|gt|ge, value: typedPrimitive}`. Each emits a separate CHECK; SQL AND semantics apply. Boolean checks support equality/inequality only; JSON checks are unsupported. SQL permits NULL in checks/unique keys as documented by the databases. Character ordering follows database collation. Primary keys require nonnullable columns; duplicates/repeated key columns rejected. Foreign keys must reference ordered declared primary/unique keys with exactly matching logical type options; unique indexes alone do not qualify. SET NULL requires all referencing columns nullable. Both ON UPDATE and ON DELETE are explicit and allow NO ACTION, RESTRICT, CASCADE, SET NULL.

Stable table/column IDs are distinct from names. All emitted names are double-quoted, embedded quotes doubled, no truncation or Unicode normalization. Names reject control characters, reserved sqlite_/pg_ prefixes, and lengths over 63 UTF-8 bytes. Conservative Unicode case-folded collisions are rejected in the shared table/index/key namespace (stricter than either engine in some cases). PK/unique backing indexes have deterministic names ut_pk_ID and ut_uq_ID_POSITION, checked against user object names. Constraints scoped to tables otherwise need no user-supplied names.

Tables are topologically sorted by repeated lexicographic stable-ID scans. Self-FKs are supported and executed; multi-table cycles fail before rendering. Column order, key order, checks, indexes and all other arrays remain meaningful and are preserved. Input property order is irrelevant. Normalize by validated deep-copy and table ordering, then canonicalize with recursively sorted object keys, compact JSON, UTF-8, JSON string escapes (including U+2028/U+2029), plain minimal decimal numbers and no trailing LF for digests. schema.json adds one LF. Numeric spellings normalize; omitted defaults do not become explicit NULL.

Payload hashes cover exact UTF-8 file bytes. `manifest.core.files` lists all payloads except manifest.json with path/bytes/SHA-256. `core.specificationDigest` hashes canonical normalized request without LF; `manifest.digest` hashes canonical core without LF. There is no circular self-hash. The core records version, target, compatibility minimum, selected verification runtime, pinned verification dependencies and bounded limitations. ZIP contains sorted flat ASCII paths, STORED entries, fixed 1980-01-02 DOS timestamp without timezone-dependent extra fields and no symlinks. Identical normalized input/template gives identical ZIP bytes on the pinned runtime. Cross-JDK archive equivalence is not certified.

Assembly uses no temporary production files. 100 files / 5 MiB total uncompressed bytes includes manifest.json. Text rendering checks incremental size; packaging checks again. Decoder retains B1's 1 MiB body, 32-depth, 20,000-node, 4,096-character-string and 1,000-element limits. Generation has 100 tables / 1,000 total columns and bounded per-table collections. Preview JSON is streamed into a capped 32 MiB buffer, covering worst-case sixfold escaping plus metadata; no truncation. B1 responses stay capped at 256 KiB. Two servlet-wide generation slots cover decode through response write, no waiting queue: overload is 503 GENERATION_BUSY with Retry-After=1. The existing shared 40 POST attempts/session/60 seconds includes validate/generate/export and rejected attempts.

POST generate accepts exactly `{request: GenerationRequest}`. POST export accepts exactly `{request,expectedDigest}` (64 lowercase hex), independently repeats all checks, regenerates and returns ZIP only if the digest agrees. Mismatch is 409 PREVIEW_DIGEST_MISMATCH. Generate success uses ApiResponse with manifest/digest/findings/adminPreview/files. 422 INVALID_GENERATION_SPECIFICATION has bounded path-specific findings; unsupported template is 422 UNAVAILABLE_TEMPLATE. Other stable codes preserve B1 decoder/security behavior: 400 malformed/duplicate/invalid transport, 413 request/complexity/output/response limits, 415 media, 401 no identity, 403 access/CSRF/Origin, 429 rate, generic 503 availability/concurrency. ZIP headers are committed only after complete assembly. Responses use no-store, including early authentication rejection.

Availability is independently read on both endpoints: ENABLED permits registered users; DISABLED permits admin preview only; ABSENT denies all; FAILED gives generic 503 to all. Guest generation/export always denied, even samples. Existing filter order is unchanged. No generation activity event is persisted and no schema-derived identifiers/digests are logged. Existing metrics collect route/status/timing only. The production WAR contains no test-login endpoints, fixture server, PostgreSQL client, or SQL executor.

Forms and JSON share an in-memory draft. Unapplied JSON locks form/source selection; Apply makes editable fields available, Generate always submits exact editor JSON so duplicate keys remain detectable. Invalid JSON is preserved until correction or explicit discard. Read-only sample selection has separate state and does not overwrite the personal draft. Edits invalidate preview/export and both abort and revision/request identity checks discard late responses. Source is rendered as text. Clipboard rejection is announced; download URLs are revoked. The browser suite covers these behaviors, mobile/desktop and all ten themes. Advanced check/default/index options use the JSON section rather than a visual designer.

GenerationTest now compares complete ZIP bytes under Asia/Kolkata, America/Los_Angeles and UTC. This correction invalidates the first B2 certificate; a fresh full run is required.
