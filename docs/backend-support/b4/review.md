# B4 delivery review

Scope reviewed: new ETL contract/template, Java semantic validator and dispatch, additive catalog capability, separate in-memory frontend editor, and external disposable verification. B0–B3 production behavior and artifact templates remain unchanged; the B3 catalog test now requires its existing modules as a subset because the capability list is deliberately additive. Historical contracts and earlier HTTP ZIPs are pinned. No commit, deployment, production database access or later-sprint implementation is authorized.

Generation review: the existing raw decoder, role/feature/CSRF/Origin controls, two assembly slots, 40-attempt rate limit, no-store headers and independent export digest check are reused. Semantic checks reject duplicate/unknown mappings, missing required columns, incompatible transform ordering, ambiguous conflict keys, nullable/omitted keys, unsupported options and unsafe numeric complexity. Identifiers and source field names remain JSON data; Python template bytes never interpolate submitted values. Bundles remain bounded and deterministic.

Runtime review: strict bounded source snapshots, Decimal parsing, explicit conversion/null/default policies, parameterized adapters, preflight metadata, savepoints and current-batch rollback are implemented. Source, specification, template and destination identities bind checkpoints. SQLite identity includes file identity; PostgreSQL includes explicit endpoint/database/user and database OID. Auxiliary output paths participate in collision checks, including existing hard links. Trusted directories and immutable inputs are operator prerequisites. A zero-record initial checkpoint permits first-batch interruption recovery; advancement occurs only after database commit. Ambiguous acknowledgement fails conservatively. External checkpoints, reject file partial lines and replayed trigger effects are explicitly limited rather than described as exactly once.

Frontend review follows the React best-practices checklist: controlled fields, pure cloned updates, stable module mounts, no draft persistence, escaped text previews, abort plus revision identity, bounded request submission, labels/status/focus and mobile theme tokens. Clipboard failure preserves the draft. Invalid advanced JSON disables guided edits until explicit apply/discard. Access and module changes invalidate artifacts and pending requests.

Test corrections preserve requirements: the initial Java List.getLast call was replaced to retain release-17 compilation. PostgreSQL timestamp assertions query AT TIME ZONE UTC instead of assuming the session display offset. Native JSON nested text targets reject; CSV JSON-looking cells are text and are not inherently invalid. Explicit select accessible names resolve exact browser labels. Filling a textarea with identical content emits no React change, so the keyboard test now appends whitespace before asserting that Apply is focusable. None of these changes removes a required behavior assertion.

Evidence policy: old diagnostic passes apply only to their saved HTTP ZIPs. Final certification reruns all required gates against a fingerprint, captures commands/cwd/exit/version/input state, checks test-harness exclusion from the WAR and sanitized logs, and restores prior report bytes. Final report/continuation updates are excluded from implementation fingerprints; source/test/config changes require fresh checks. Limitations remain Windows/Python 3.14.3/PostgreSQL 17.11, finite compatibility checks, SQLite approximate NUMERIC storage, local-only sources and process-crash rather than universal power-loss guarantees.
