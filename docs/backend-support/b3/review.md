# B3 delivery review

Scope: three B3 modules through existing generation endpoints and catalog, guided frontend, separate diagnostic contract, and external verification tooling. No B4 generators, new production persistence, credentials, live execution, deployment or unrelated dependency upgrades. Existing B0/B1/B2 changes remain intact. Released B2 renderer output is protected by actual HTTP ZIP byte pins, and historical model/transport/manifest contracts by file hashes.

Migration review: maps use stable IDs and exact before/after names; no drop/add rename inference. Every model field affecting columns, keys, FKs, checks and indexes is compared or validated; unsupported differences block the complete plan. Column order changes and occupied rename targets are conservatively blocked. Runner integrity check precedes execution; guard failures abort before mutation, transactions and locks cover the procedure, and backup/external-review limitations are explicit. The reserved temporary guard name now blocks an input table that could otherwise shadow DDL. down.sql exists only for index/name reversal, never for dropping added columns. Metadata coverage is deliberately finite and documented.

View review: only schema-resolved references, allowlisted operators and typed literals render. Database identifiers and literals reuse B2 quoting. Unknown aliases, output collisions, incompatible comparisons, equality to NULL and bare ungrouped projections fail before output. No arbitrary parser, parameter interpolation, function evaluation or SQL execution exists in production. Both engines must execute SQL extracted from actual HTTP ZIPs.

Evaluator review: diagnostic types/defaults stay inert and do not weaken SchemaGeneration. Eight rules have executable positive, negative and not-applicable cases. Invalid prerequisite references/types skip dependent checks rather than producing type-mismatch cascades. Findings have fixed text and bounded contract paths; canonical report files are deterministic, error reports remain downloadable, and SQL eligibility is explicitly not established. Ambiguous IDs, structural excess and pathological number expansion are rejected.

Access/resource/privacy review: all modules share stored CSRF, Origin, strict availability, guest denial, raw decoder limits, rate budget and two-slot assembly boundary. Export revalidates and compares digest before ZIP headers. Output and JSON serialization bounds remain independent. Bundles are transient; activity persistence is absent. Test sessions and PostgreSQL tooling remain outside the WAR. Runtime scripts stop only owned processes and remove session files; diagnostic data is synthetic.

React best-practices review: component state remains local, custom drafts stay in memory across module switches, effects clean up pending work and revision identity protects against uncancellable responses. Invalid JSON cannot be silently overwritten by guided controls. Native labeled fields, named status regions, severity filters and focus navigation are used. Source and SQL render as text. Downloads revoke object URLs. Existing Playwright verification is reused as requested, with actual WAR filters and a synthetic session fixture; screenshots were inspected for mobile layout. Fixed application headers may appear within full-height element screenshots when scrolled; this is screenshot composition, not a detached page element.

Test corrections: Tool family is a wrapped label containing a select; the initial exact label locator did not resolve despite visible controls. It was changed to the existing B1 locator convention without removing assertions. The first combined-column test exceeded the frozen per-table limit before reaching the combined limit; the corrected fixture distributes columns across six valid tables. These were test defects, not weakened validation.

Final verdict and counts are only those in the fresh sprint-pass.md/evidence.json. Diagnostic successes do not certify later source changes. Hosted CI, arbitrary customer database migration safety, Java 17 runtime, other PostgreSQL versions and B7 load qualification are not claimed. G10 requires unchanged certification inputs and the reviewed B4 boundary.
