# Deployment runbook — not authorization

Release blocked until checklist and product approval. Generation service, Java starter and Python/Redis are three distinct deployment targets. No public endpoint is used for load tests.

Generation service: from repository root build with `docker build -f Useful-Tools/Dockerfile .` on approved isolated builder. Root context includes contracts; backend source alone is insufficient. Do not include database dumps or secrets in the image. Record base image digests, resulting image/WAR/frontend hashes and dependencies. Provision a reviewed application DB backup on persistent /databases volume before startup; Docker now fails if the file is absent/empty. DatabaseInitializer is not full account/schema provisioning. Bind SQLITE_DB_PATH explicitly; restrict file access to service account. Keep Backend Support disabled and verify direct HTTP denial before enabling in staging. Proxy /api same-origin; qualify actual Origin/CSRF/Secure-cookie behavior through intended Vercel/Railway routing. Floating base tags and actual JDK17 execution remain unqualified; pin approved digests before release.

Java starter: follow exported README/env names. Empty auth DB initialization only; root-context direct HTTPS, selected DB driver and runtime, one instance. Secrets via operator delivery, not artifact edits. Verify register/login/profile/logout, restart revocation and fail-closed missing configuration on disposable data. Existing downloaded artifacts remain independent.

Python: Python3.14 one worker, root URL, direct TLS, proxy_headersFalse; no trusted-forwarded workaround. Qualify managed Redis TLS certificate validation, dedicated ACL/key namespace, maxmemory/eviction, persistence, deadlines and network policy. B6 Windows Cygwin Redis is test infrastructure only. DB workers8, hash2, Redis connections16 and server concurrency64 require target load/fault measurements. Preserve isolation from Java auth DB/sessions.

Preflight: artifact signatures/hashes, backup restore, permissions, secrets, provider egress, monitoring redaction and rollback owners. Postflight staging: synthetic registration lifecycle, sample generation/export digest, disabled/guest/CSRF denies, expected latency/errors and no sensitive logs. Never automatically enable production or apply customer DB migrations.
