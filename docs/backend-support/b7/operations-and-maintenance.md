# Operations and maintenance

Allowed telemetry: module/target/template enums, route/status/error-code classes, elapsed duration, bounded request/output byte counts, busy/rate rejects and resource gauges. Forbidden: schemas/table/column names, source rows, generated code, passwords/hashes, session/CSRF/CAPTCHA tokens, environment values and custom filenames. Review infrastructure access logs as well as application logs. Existing generator logs/metrics use fixed activity and route metadata; inspect captured sentinel checks in prior chain. Alert payloads must use aggregate counts only.

Proposed alert (not accepted SLO):5xx>2% over10min with>=50 requests triggers review; low traffic inspect individual sanitized errors. Also watch two-slot503,429,413, pool/hash saturation, Redis503/latency, expiry/login failure trends, process memory/disk and DB health. Validate thresholds on pilot/staging; no production alert guarantee claimed. Assign on-call, security escalation and product communications before release; currently unassigned.

Weekly dependency/advisory triage and monthly reproducible rebuild proposed for maintainer approval. Inventory application plus exported dependencies and native runtimes; assess reachability with vendor advisories. Template changes require new versions, retained provenance, regenerated setup/tests/OpenAPI/parity and affected runtime matrices. Report existing-download impact. Roll back or disable materially unsafe templates without rewriting historical hashes. No automatic upgrades or notifications installed.

Support intake: artifact template/digest, supported topology, sanitized error code, runtime versions and minimal synthetic reproduction. Never request customer DB dumps or credentials. Prioritize security/data-loss, correctness/accessibility, then usability. Publish known limitations and link rollback-runbook; incident owner records cause/remediation/retest. Review after two weeks of any authorized rollout, not automatically from this local certification date.
