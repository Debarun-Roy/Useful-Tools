# Rollback and restore procedures

Generation service: record current and previous image/WAR/frontend/catalog hashes plus DB snapshot. Disable Backend Support server-side via existing admin toggle before replacing artifacts; this is global, not cohort routing. Confirm registered-user generate/export403 and admin-preview policy. Stop writes, take consistent SQLite backup using backup API (not copying live WAL incompletely), verify integrity and restore into a separate path first. Replace app/template catalog with known-good compatible version. Reapply disabled state and smoke auth/favorites/search/admin/generation denial. Never restore database blindly over later user writes; reconcile ownership and data first.

Generated Java/Python: operator takes DB backup and records configuration keys (no values in reports), schema version and artifact hash. On failure stop new writes, restore compatible application/config; database rollback requires inspected backup and explicit handling of postbackup writes. No destructive migration inverse is a data-recovery guarantee. Python restart changes namespace and invalidates existing sessions; Java process restart loses memory sessions. Do not FLUSHDB/scan/delete other tenants' keys. Redis eviction/loss can terminate sessions; persistence/restart behavior must match selected target policy.

Local rehearsal: B7 exported schema→ETL→view uses SQLite online backup, deletes data, restores and verifies1000 rows/view; B3 executes reverse rename/index and injected transactional rollback on both engines. B5/B6 exercise restart revocation and compatible empty/versioned DB initialization. These do not prove a production image rollback, remote Redis persistence or target backup procedure; complete those in the intended environment.

Already downloaded artifacts cannot be recalled. Identify affected templateVersion and manifest hash, send correction notice only with authorization, publish regeneration instructions/version diff and explicitly state which data/schema remains compatible. Do not silently replace old bytes. Owner/escalation unassigned until release approval.
