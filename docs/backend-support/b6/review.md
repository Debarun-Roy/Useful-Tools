# B6 focused self-review

This is implementation self-review, not independent security review. Final execution status is exclusively in sprint-pass.md/evidence.json.

Reviewed PythonAuthGeneration, additive dispatch/catalog, v0.6.0 schema, fixed templates, RestEditor target state, generator/browser tests, real ASGI/Redis adapters, shared parity and certification cleanup. Java AuthGeneration/AuthOpenApi and all released template/contract bytes are pinned. Python reuses accepted policy validation via inert metadata translation; its output is rendered separately. No generated code is executed by UsefulTools. WAR inspection excludes external fixtures and compiled generated applications.

Security review covers manual bounded JSON before Pydantic, explicit safe envelopes, transport/route/body/session/Origin/CSRF precedence, exact origins, opaque cookies, root deployment restriction, no forwarded trust, session locking and no late save, Redis error propagation, bounded registries/pools, Argon2 parameters and malformed hash handling, parameterized DB access/rollback, strict provider transport/semantics, no hidden credentials/bypasses and safe startup. Tests use only synthetic data and disposable stores.

Corrections during development: pinned the transitive itsdangerous dependency after clean-install inspection; added strict Pydantic models after manual wire validation; retained capacity until underlying executor work finishes despite cancellation; normalized only case-insensitive HTTP header names in the shared test client; fixed explicit target label and Python selection after page reload in browser setup; placed pytest temporary files under the owned run after a global temporary-directory ACL error. Final identifier review found that names such as datetime could shadow standard-library imports; the semantic denylist now covers Python3.14 standard modules and pinned dependency import names, with regression cases. Runtime env names that collide with worker/Python launch configuration are rejected. The first full regression run exposed a B1 privacy false positive: its substring search matched public sessionStore metadata. The correction recursively rejects actual sensitive field names and every synthetic session/CSRF value, retaining the privacy requirement without prohibiting the authorized capability description. No valid assertion was removed. B5 obsolete Python-unavailable assertions were replaced with Java version/selection preservation because B6 explicitly authorizes availability.

React review: separate mounted editors retain independent invalid/valid drafts; existing abort/revision identities protect stale previews/exports. No new request effect on target switch, no hook in conditionals, explicit labeled selector and existing accessible field/error/preview structure. Browser suite covers role/feature restrictions, keyboard, themes, mobile and races.

Verification review: comparator uses the same call methods, sequence and OpenAPI validation for both languages and both DBs; only validated UUID/CSRF fields normalize. Concurrent race order is not compared, but postconditions are identical and revoked IDs must remain anonymous. Real Redis serialization/deletion/TTL/outage/restart and capacity are additional Python store tests. ASGI crafted scopes supplement actual socket/browser flows for forwarding/root-path/misleading-length cases.

Remaining risk: single worker and volatile rate/namespace registry, Redis operation loss/failure, operator TLS/ACL/dependency maintenance, unsupported proxy/subpath/multi-instance deployments, finite test concurrency rather than load qualification. Redis Windows Cygwin build is a pinned local test provisioner, not production support. B7 must commission independent security review and load/UAT/deployment qualification before release.

Additional read-only review confirmed Gson escapes U+2028/U+2029 even with HTML escaping disabled (200 separators serialize to1202 Java characters versus202 in Python). Python now applies the same escaped-size measurement for the frozen8192 profile preference limit; the shared socket suite checks both oversized separator maps and a valid preserved pair. This fixes behavior without changing Java templates or banning valid Unicode.
